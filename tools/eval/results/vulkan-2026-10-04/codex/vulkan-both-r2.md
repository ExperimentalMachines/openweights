1. **[P1] OpenWeights loses Vulkan diagnostics before checking them.** [ExecuTorchEngine.kt:658](~/mobile-inference/core/engine/src/main/kotlin/io/github/alpharomercoma/openweights/core/engine/ExecuTorchEngine.kt:658) wraps calls, but [NativeExecuTorchBridge.kt:130](~/mobile-inference/core/engine/src/main/kotlin/io/github/alpharomercoma/openweights/core/engine/NativeExecuTorchBridge.kt:130) still treats any `max_context_len` mention as overflow. A Vulkan failure containing recent metadata logs becomes `ContextWindowExceededException` without its original message or cause. `gpuChecked` therefore misses the incompatibility during generation, prefill, warm-up, and image prefill. **Fix:** classify incompatibility before bridge translation; narrow overflow matching and retain original causes.

2. **[P1] ExecuServe install IDs still collide between backends.** [HfCatalog.kt:53](~/execuserve/shared/catalog/src/commonMain/kotlin/org/experimentalmachines/execuserve/catalog/HfCatalog.kt:53) derives the ID solely from the basename. `xnnpack/Qwen3-8da4w.pte` and `vulkan/Qwen3-8da4w.pte` share an installation directory and download key. Installing one makes both appear installed; another installation can replace the existing backend. The added test uses an already-distinct Vulkan basename. **Fix:** include backend identity in GPU install IDs while preserving existing CPU IDs.

3. **[P1] OpenWeights’ naming fix still collides in Vulkan-named repositories.** [ExecuTorchFileName.kt:79](~/mobile-inference/core/common/src/commonMain/kotlin/io/github/alpharomercoma/openweights/core/common/model/ExecuTorchFileName.kt:79) checks the combined repository/file name before adding the Vulkan suffix. For `publisher/Qwen3-Vulkan`, both `xnnpack/Qwen3-8da4w.pte` and `vulkan/Qwen3-8da4w.pte` become `Qwen3-Vulkan-Qwen3-8da4w.pte`. The repository’s marker suppresses disambiguation. **Fix:** derive installation identity from the file’s backend/path, independently of repository markers.

4. **[P2] ExecuServe can pull the wrong backend despite an explicit path.** [CatalogRepository.kt:59](~/execuserve/android/app/src/main/kotlin/org/experimentalmachines/execuserve/app/models/CatalogRepository.kt:59) strips both paths before matching. Requesting `vulkan/Qwen3-8da4w.pte` can select the XNNPACK variant first, or silently substitute it when Vulkan is unavailable. **Fix:** match supplied paths exactly; allow basename lookup only when unambiguous.

The refusal matcher correctly excludes unrelated errors and out-of-device-memory. Discovery’s path precedence is fixed. ExecuServe’s overflow matcher and stale-list filtering/download guard address those earlier findings.
